# /cv — 独立 API 盲审交叉验证

通过外部独立 API（如 DeepSeek / Kimi）对技术文档进行盲审，评审结果与当前 Claude Code 会话物理隔离，解决单一 AI 模型长期使用导致的记忆衰退与注意力分散问题，实现真正的交叉验证。

## 当前模式判断

请分析 `$ARGUMENTS` 的内容，按以下优先级判断执行哪种模式：

1. **如果为空、只有 `help`、`-h` 或 `--help`** → 执行【帮助模式】
2. **其他情况** → 执行【轻量盲审模式】

---

## 【帮助模式】

当 `$ARGUMENTS` 为空、只有 `help`、`-h` 或 `--help` 时，进入帮助模式。

请使用 `Read` 工具读取文件 `docs/cv_help.md`，然后将其中的 Markdown 内容直接展示给用户。不要包裹在代码块中，保持原样输出即可。

---

## 【轻量盲审模式】

### Step 1：解析参数

从 `$ARGUMENTS` 中提取：
- **第一个参数** → `文件路径`
- **剩余所有文本** → `定向指令`（可能为空字符串）

### Step 2：路径验证与读取

使用 `Read` 工具尝试读取用户提供的文件路径。

- **如果 Read 返回错误（文件未找到）**：
  向用户展示以下提示，并**停止执行，等待用户重新提供路径**：

  ```
  找不到指定路径：[用户原始输入的路径]

  可能的原因：
  - 路径拼写错误，或文件确实不存在
  - 使用了错误的路径分隔符
  - 当前工作目录与预期不符

  请确认后重新输入。支持以下格式：
  - 相对路径：docs/design.md
  - Windows 绝对路径：D:/project/docs/design.md 或 D:\project\docs\design.md
  - Linux / macOS：/home/user/docs/design.md

  Windows 用户建议使用正斜杠 / 以避免转义问题。
  ```

  收到用户重新提供的路径后，再次尝试 `Read`，直到成功或用户明确取消。

- **如果 Read 成功**：
  向用户展示文件前 20 行摘要，格式如下：

  ```
  已定位文件：[文件绝对路径]
  文件前 20 行摘要：
  ────────────────────────────────
  [内容摘要]
  ────────────────────────────────
  正在调用独立 API 进行盲审，请稍候...
  ```

### Step 3：调用盲审

使用 `Bash` 调用底层 `cv-review` CLI。注意：
- 文件路径必须用**双引号**包裹，防止空格或特殊字符导致解析错误
- 若用户提供了定向指令，追加 `--instruction` 参数
- **Windows 路径兼容性**：直接原样传递用户输入的路径即可，`cv-review` 内部使用 `pathlib.Path` 会自动处理各种分隔符

```bash
cv-review --file "<用户输入的文件路径>" [<若定向指令非空> --instruction "<定向指令>"]
```

### Step 4：展示评审结果

将 `Bash` 的 stdout 内容完整展示给用户。在结果前加上标识：

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
独立 API 盲审意见（与当前会话物理隔离）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
[评审意见内容]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### Step 5：交互闭环

询问用户：

```
是否需要我根据以上盲审意见直接修改该文档？
   （回复"是"直接修改，回复"否"或忽略则结束）
```

- 若用户明确同意（回复包含"是"/"yes"/"y"/"好"/"改"等）：
  使用 `Edit` 工具直接修改原文件，修改后向用户汇报变更点。
- 若用户拒绝或没有明确同意：结束，等待用户下一步指令。

## 路径兼容性处理规范（重要）

在执行过程中，你必须特别注意路径的跨平台兼容性：

1. **接收阶段**：无论用户输入什么路径格式（`/`、`\`、`//`、`\\`、带盘符、不带盘符），都原样保留传递给 `Read` 和 `Bash`。

2. **验证阶段**：始终使用 `Read` 工具验证路径是否存在。`Read` 工具本身具备跨平台路径解析能力。

3. **失败处理**：只要 `Read` 返回"文件未找到"或类似错误，**绝不要猜测路径或自动修正**，必须向用户明确报告并请求重新输入。

4. **传递阶段**：在组装 `Bash` 命令时，路径必须用**双引号 `"`** 包裹，防止以下情况导致命令解析错误：
   - 路径中包含空格（如 `My Documents/design.md`）
   - Windows 反斜杠被 Shell 误解为转义符

5. **展示阶段**：向用户展示路径时，优先展示**绝对路径**（如果 `Read` 成功，你可以从结果中得知实际解析后的绝对路径），让用户明确知道操作的是哪个文件。
