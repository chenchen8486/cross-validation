# /cv — 独立 API 盲审交叉验证

通过外部独立 API（如 DeepSeek / Kimi）对技术文档进行盲审，评审结果与当前 Claude Code 会话物理隔离，解决单一 AI 模型长期使用导致的记忆衰退与注意力分散问题，实现真正的交叉验证。

---

## 当前模式判断

请分析 `$ARGUMENTS` 的内容，按以下优先级判断执行哪种模式：

1. **如果为空、或以 `help`、`-h`、`--help` 开头** → 执行【帮助模式】
2. **如果第一个参数是 `debate`（且不包含路径特征）** → 执行【Debate 子命令废弃提示】
3. **如果第一个参数符合路径特征** → 执行【轻量盲审模式】
4. **其他所有情况** → 执行【智能意图模式】（新增）

### 路径特征判断规则（鲁棒性设计）

以下任一条件成立，即视为**路径特征**：

- 包含目录分隔符：`/`、 `\`、 `//`、 `\\`
- 包含 Windows 盘符：单字母后跟冒号，如 `C:`、`D:`、`E:`、`c:`、`d:`
- 以 `.` 开头：如 `.gitignore`、`..`、`./config.py`
- 包含常见文件扩展名后缀（不区分大小写）：
  `.md`、`.txt`、`.py`、`.json`、`.yaml`、`.yml`、`.toml`、
  `.js`、`.ts`、`.tsx`、`.jsx`、`.java`、`.go`、`.rs`、
  `.c`、`.cpp`、`.h`、`.hpp`、`.cs`、`.php`、`.rb`、
  `.sh`、`.bat`、`.ps1`、`.sql`、`.html`、`.css`、`.scss`
- 等于 `.` 或 `..`

> **设计原则**：宁可误判为路径（由 `Read` 验证失败后友好提示重试），也绝不误判为意图，避免用户本来想指定文件却被当作自然语言处理。

## 【帮助模式】

当 `$ARGUMENTS` 为空、或以 `help`、`-h`、`--help` 开头时，进入帮助模式。

1. **尝试读取外部帮助文档**：
   使用 `Read` 工具读取文件 `docs/cv_help.md`。
   - 如果 `Read` 成功：将其中的 Markdown 内容直接展示给用户（不要包裹在代码块中）。
   - 如果 `Read` 返回错误（文件未找到）：进入步骤 2。

2. **Fallback 内联帮助**（当外部文件不存在时展示）：

   ```
   # /cv 命令使用指南

   ## 场景速查
   | 你想做什么 | 命令 |
   |:---|:---|
   | 轻量盲审（指定文件） | `/cv <文件> [指令]` |
   | 智能意图（自动扫描） | `/cv <自然语言请求>` |
   | 多轮闭环博弈 | `/cv_debate <文件> [指令]` |
   | 查看帮助 | `/cv help` |

   ## 示例
   /cv docs/api-design.md
   /cv src/core/auth.py 审查登录函数异常处理
   /cv 你帮我校验当前工程的代码合理吗
   /cv_debate docs/requirement.md
   ```

   展示后结束。

当 `$ARGUMENTS` 的第一个参数是 `debate`（且不包含路径特征）时，向用户展示：

```
⚠️ 注意：`/cv debate` 子命令已废弃。

请直接使用独立的 `/cv_debate` 命令替代：
   /cv_debate [文件路径] [定向指令]

例如：
   /cv_debate docs/requirement.md
   /cv_debate docs/draft-design.md 重点关注高并发一致性
```

展示后停止执行。

## 【轻量盲审模式】

### Step 1：解析参数

从 `$ARGUMENTS` 中提取：
- **第一个参数** → `文件路径`
- **剩余所有文本** → `定向指令`（可能为空字符串）

> **定向指令去重**：如果用户误将底层 CLI 的参数格式输入进来（如 `file.md --instruction "check logic"`），导致定向指令以 `--instruction` 开头，请在提取时**去除该前缀及其后的空格**，只保留真正的指令内容。

### Step 2：路径验证与读取

使用 `Read` 工具尝试读取用户提供的文件路径。

- **如果 Read 返回错误（文件未找到）**：
  向用户展示以下提示，并**停止执行，等待用户重新提供路径**：

  ```
  找不到指定路径：[用户原始输入的路径]

  可能的原因：
  - 路径拼写错误，或文件确实不存在
  - 使用了错误的路径分隔符
  - 当前工作目录与预期不符

  请确认后重新输入。支持以下格式：
  - 相对路径：docs/design.md
  - Windows 绝对路径：D:/project/docs/design.md 或 D:\project\docs\design.md
  - Linux / macOS：/home/user/docs/design.md

  Windows 用户建议使用正斜杠 / 以避免转义问题。
  ```

  收到用户重新提供的路径后，再次尝试 `Read`，直到成功或用户明确取消。

- **如果 Read 成功**：
  向用户展示文件前 20 行摘要，格式如下：

  ```
  已定位文件：[文件绝对路径]
  文件前 20 行摘要：
  ────────────────────────────────
  [内容摘要]
  ────────────────────────────────
  ```

### Step 3：前置依赖检查

在调用底层 CLI 之前，使用 `Bash` 验证 `cv-review` 是否可用：

```bash
cv-review --version 2>/dev/null || echo "NOT_FOUND"
```

- **如果输出包含 `NOT_FOUND` 或返回命令未找到错误**：
  向用户展示：
  ```
  未检测到 cv-review 命令。请先执行以下命令安装：
     pip install -e .
  并确保安装目录的 Scripts/ 或 bin/ 已在系统 PATH 中。
  ```
  停止执行。

- **如果检查通过**：继续执行 Step 4。

### Step 4：调用盲审

使用 `Bash` 调用底层 `cv-review` CLI。注意：
- 文件路径必须用**双引号**包裹，防止空格或特殊字符导致解析错误
- 若用户提供了定向指令，追加 `--instruction` 参数
- **Windows 路径兼容性**：直接原样传递用户输入的路径即可，`cv-review` 内部使用 `pathlib.Path` 会自动处理各种分隔符

```bash
cv-review --file "<用户输入的文件路径>" [<若定向指令非空> --instruction "<定向指令>"]
```

**错误处理**：执行 `Bash` 后，检查返回码。
- 如果返回码为 0：继续 Step 5。
- 如果返回码非 0：
  1. 将 stderr 内容完整展示给用户。
  2. 如果 stderr 包含 "API"、"认证"、"密钥"、"Authentication"、"Key" 等字样：
     提示用户检查环境变量 `DEEPSEEK_API_KEY` 和 `KIMI_API_KEY` 是否已正确配置。
  3. 如果 stderr 包含 "文件未找到"、"FileNotFoundError"：
     提示用户检查文件路径。
  4. 否则：
     提示用户检查网络连接，或尝试带上 `-v` 参数查看详细日志：
     `cv-review --file "<路径>" -v`
  停止执行。

### Step 5：展示评审结果

将 `Bash` 的 stdout 内容完整展示给用户。在结果前加上标识：

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
独立 API 盲审意见（与当前会话物理隔离）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
[评审意见内容]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### Step 6：交互闭环

询问用户：

```
是否需要我根据以上盲审意见直接修改该文档？
   （回复"是"直接修改，回复"否"或忽略则结束）
```

- 若用户明确同意（回复包含"是"/"yes"/"y"/"好"/"改"等）：
  使用 `Edit` 工具直接修改原文件，修改后向用户汇报变更点。
- 若用户拒绝或没有明确同意：结束，等待用户下一步指令。

## 【智能意图模式】（新增）

当 `$ARGUMENTS` 整体**不满足路径特征**、**不是帮助命令**、且**第一个参数不是 `debate`** 时，进入智能意图模式。

该模式将用户输入视为自然语言请求，自动扫描工程文件、聚合内容后提交盲审。

### Step 1：意图解析

将 `$ARGUMENTS` 整体保存为 `user_query`。

分析 `user_query` 的关键词，判断用户关注的领域：
- **代码/工程/项目/源码/程序/逻辑/算法/函数/类/接口/模块** → 以扫描代码文件为主
- **文档/设计/方案/需求/架构/Readme/readme/规范/标准** → 以扫描文档文件为主
- **无明确偏向或同时涉及** → 同时扫描代码和文档

### Step 2：文件扫描

使用 `Glob` 工具在当前工作目录扫描相关文件。

**扫描策略**：

1. **代码文件扫描**：
   - 优先扫描标准源码目录：`src/**/*.py`、`core/**/*.py`、`models/**/*.py`、`utils/**/*.py`
   - 若标准目录无结果，回退到：`*.py`、`*.js`、`*.ts`、`*.java`、`*.go`、`*.rs`、`*.c`、`*.cpp`、`*.cs`

2. **文档文件扫描**：
   - `docs/**/*.md`
   - `README.md`
   - `*.md`

3. **配置文件扫描**（若用户提及配置）：
   - `config/**/*`
   - `pyproject.toml`、`package.json`、`requirements.txt`

**排除规则**（Glob 获取结果后手动过滤，满足任一即排除）：
- 路径中包含以下目录：`venv/`、`__pycache__/`、`.git/`、`.pytest_cache/`、`node_modules/`、`dist/`、`build/`、`temp/`、`outputs/`、`.idea/`、`.vscode/`
- 文件名以 `test_` 开头（如 `test_api.py`）
- 文件名以 `_test.` 结尾（如 `api_test.py`）
- 路径中包含 `tests/` 目录

**空结果处理**：
如果经过上述扫描和过滤后，文件列表为空：
```
未在工程中检测到可评审的文件。可能原因：
- 当前目录不包含任何源码或文档
- 所有文件均被排除规则过滤

请尝试以下操作：
1. 确认当前工作目录是否正确
2. 直接指定文件路径：/cv <文件路径>
```
停止执行。

### Step 3：文件筛选与读取

从扫描结果中，使用 `Read` 工具读取最多 **10 个** 最重要文件的内容。

**筛选优先级**：
1. `README.md`（若存在，必入选）
2. 核心入口文件（如 `src/cv_review/cli.py`、`main.py`、`app.py`）
3. 核心算法/业务逻辑文件
4. 配置文件（如 `pyproject.toml`）
5. 其他按文件名字母序排列

**Read 错误处理**：
使用 `Read` 读取每个文件时：
- 如果 `Read` 成功：获取文件内容，进入大小控制流程。
- 如果 `Read` 返回错误（权限不足、编码错误、文件被占用等）：
  跳过该文件，在聚合文档中注明：
  ```markdown
  ## 文件：[路径]

  （读取失败：[错误原因]）
  ```
  继续处理下一个文件，不计入 10 个文件上限。

**大小控制**：
- 读取过程中估算累计字符数。若累计超过 **80KB**，停止读取后续文件，仅保留已读取的内容。
- 对于单个超过 20KB 的文件，只读取前 150 行并追加注释 `（后续内容已截断）`。

### Step 4：内容聚合

将读取到的文件内容聚合成一个临时 Markdown 文件。

1. 使用 `Bash` 创建 `temp/` 目录（若不存在）：
   ```bash
   mkdir -p temp 2>/dev/null || mkdir temp
   ```

2. 使用 `Write` 工具写入文件 `temp/cv_intent_bundle.md`，内容格式如下：

   ```markdown
   # 工程文件汇总（由 /cv 智能意图模式自动生成）

   > 用户原始请求：[user_query]

   ---

   ## 文件：[相对路径]

   ```[语言标识]
   [文件完整内容，或读取失败提示]
   ```
   ```

   > 语言标识规则：`.py` → `python`，`.js` → `javascript`，`.ts` → `typescript`，`.java` → `java`，`.go` → `go`，`.rs` → `rust`，`.md` → `markdown`，其他 → 空或根据扩展名推断。

   如果 `temp/cv_intent_bundle.md` 已存在，直接覆盖（临时文件无需保留历史版本）。

### Step 5：调用盲审

**前置依赖检查**（同轻量盲审模式 Step 3）：
先验证 `cv-review` 命令是否可用。若不可用，提示安装并停止执行。

**引号安全处理**：
组装 Bash 命令前，检查 `user_query` 是否包含双引号 `"` 或单引号 `'`。
- 如果包含引号：**不传递 `--instruction` 参数**（因为聚合文件 `temp/cv_intent_bundle.md` 的正文第一段已经完整包含了用户原始请求，底层 reviewer 会看到）。
- 如果不包含引号：正常传递 `--instruction "[user_query]"`。

**执行命令**：
```bash
cv-review --file "temp/cv_intent_bundle.md" [<若 user_query 不含引号> --instruction "[user_query]"]
```

向用户展示等待提示：
```
已自动扫描并聚合 [N] 个工程文件至 temp/cv_intent_bundle.md，
正在调用独立 API 进行盲审，请稍候...
```

**错误处理**（同轻量盲审模式 Step 4）：
- 如果返回码非 0，展示 stderr 并给出针对性提示（API Key / 网络 / 日志排查）。
- 停止执行。

### Step 6：展示评审结果

将 `Bash` 的 stdout 内容完整展示给用户。在结果前加上标识：

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
独立 API 盲审意见（与当前会话物理隔离）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
[评审意见内容]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

在结果展示后，追加一行说明：
```
本次评审基于自动扫描的 [N] 个文件聚合文档。如需针对单个文件深度审查，请使用 /cv <文件路径>。
```

### Step 7：交互闭环与清理

询问用户：

```
是否需要我根据以上盲审意见修改原始工程文件？
   （回复"是"，我将尝试定位并修改具体文件；
    回复"否"或忽略则结束本次评审。）
```

- 若用户明确同意：根据评审意见中提及的具体文件，使用 `Edit` 工具尝试修改原始文件。修改后向用户汇报变更点。
- 若用户拒绝或忽略：询问是否删除临时文件：
  ```
  是否删除临时文件 temp/cv_intent_bundle.md？（回复"是"删除，回复"否"或忽略则保留）
  ```
  - 若用户同意删除：使用 `Bash` 执行 `rm temp/cv_intent_bundle.md`（Windows 下可用 `del` 或 Git Bash 的 `rm`）。
  - 否则：保留临时文件。结束。

## 路径兼容性处理规范（重要）

在执行过程中，你必须特别注意路径的跨平台兼容性：

1. **接收阶段**：无论用户输入什么路径格式（`/`、 `\`、 `//`、 `\\`、 带盘符、不带盘符、正斜杠、反斜杠混合），都原样保留传递给 `Read` 和 `Bash`。

2. **验证阶段**：始终使用 `Read` 工具验证路径是否存在。`Read` 工具本身具备跨平台路径解析能力。

3. **失败处理**：只要 `Read` 返回"文件未找到"或类似错误，**绝不要猜测路径或自动修正**，必须向用户明确报告并请求重新输入。

4. **传递阶段**：在组装 `Bash` 命令时，路径必须用**双引号 `"`** 包裹，防止以下情况导致命令解析错误：
   - 路径中包含空格（如 `My Documents/design.md`）
   - Windows 反斜杠被 Shell 误解为转义符

5. **展示阶段**：向用户展示路径时，优先展示**绝对路径**（如果 `Read` 成功，你可以从结果中得知实际解析后的绝对路径），让用户明确知道操作的是哪个文件。

6. **盘符兼容性**：Windows 路径的盘符大小写不敏感（`C:` 与 `c:` 等价），且支持混合分隔符（如 `D:/project\docs/design.md`）。底层 `pathlib.Path` 会自动标准化，无需在提示词层做额外处理。
