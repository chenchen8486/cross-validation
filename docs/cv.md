# /cv — 独立 API 盲审交叉验证

通过外部独立 API（如 DeepSeek / Kimi）对技术文档进行盲审，评审结果与当前 Claude Code 会话物理隔离，解决单一 AI 模型长期使用导致的记忆刷退货与注意力分散问题，实现真正的交叉验证。

## 当前模式判断

请分析 `$ARGUMENTS` 的内容，按以下优先级判断执行哪种模式：

1. **如果为空、只有 `help`、`-h` 或 `--help`** → 执行【帮助模式】
2. **如果以 `debate` 开头（不区分大小写）** → 执行【Debate 向导模式】
3. **其他情况** → 执行【轻量盲审模式】

---

## 【帮助模式】

当 `$ARGUMENTS` 为空、只有 `help`、`-h` 或 `--help` 时，进入帮助模式。

请使用 `Read` 工具读取文件 `docs/cv_help.md`，然后将其中的 Markdown 内容直接展示给用户。不要包裹在代码块中，保持原样输出即可。

---

## 【轻量盲审模式】

### Step 1：解析参数

从 `$ARGUMENTS` 中提取：
- **第一个参数** → `文件路径`
- **剩余所有文本** → `定向指令`（可能为空字符串）

### Step 2：路径验证与读取

使用 `Read` 工具尝试读取用户提供的文件路径。

- **如果 Read 返回错误（文件未找到）**：
  向用户展示以下提示，并**停止执行，等待用户重新提供路径**：

  ```
  ⚠️ 找不到指定路径：[用户原始输入的路径]

  可能的原因：
  • 路径拼写错误，或文件确实不存在
  • 使用了错误的路径分隔符
  • 当前工作目录与预期不符

  请确认后重新输入。支持以下格式：
  • 相对路径：docs/design.md
  • Windows 绝对路径：D:/project/docs/design.md 或 D:\project\docs\design.md
  • Linux / macOS：/home/user/docs/design.md

  💡 Windows 用户建议使用正斜杠 / 以避免转义问题。
  ```

  收到用户重新提供的路径后，再次尝试 `Read`，直到成功或用户明确取消。

- **如果 Read 成功**：
  向用户展示文件前 20 行摘要，格式如下：

  ```
  ✅ 已定位文件：[文件绝对路径]
  📄 文件前 20 行摘要：
  ────────────────────────────────
  [内容摘要]
  ────────────────────────────────
  🚀 正在调用独立 API 进行盲审，请稍候...
  ```

### Step 3：调用盲审

使用 `Bash` 调用底层 `cv-review` CLI。注意：
- 文件路径必须用**双引号**包裹，防止空格或特殊字符导致解析错误
- 若用户提供了定向指令，追加 `--instruction` 参数
- **Windows 路径兼容性**：直接原样传递用户输入的路径即可，`cv-review` 内部使用 `pathlib.Path` 会自动处理各种分隔符

```bash
cv-review --file "<用户输入的文件路径>" [<若定向指令非空> --instruction "<定向指令>"]
```

### Step 4：展示评审结果

将 `Bash` 的 stdout 内容完整展示给用户。在结果前加上标识：

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
🔍 独立 API 盲审意见（与当前会话物理隔离）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
[评审意见内容]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### Step 5：交互闭环

询问用户：

```
💬 是否需要我根据以上盲审意见直接修改该文档？
   （回复"是"直接修改，回复"否"或忽略则结束）
```

- 若用户明确同意（回复包含"是"/"yes"/"y"/"好"/"改"等）：
  使用 `Edit` 工具直接修改原文件，修改后向用户汇报变更点。
- 若用户拒绝或没有明确同意：结束，等待用户下一步指令。

## 【Debate 向导模式】

### Step 1：解析初始输入

去掉 `$ARGUMENTS` 开头的 `debate` 关键字（不区分大小写），分析剩余文本：
- 如果剩余文本看起来像路径（包含 `/`、`.`、盘符如 `C:`、或反斜杠 `\`），则将其作为**初始文件路径**
- 剩余部分（如果有）作为**初始定向指令**
- 如果没有剩余文本，则**初始文件路径为空**，后续交互询问

### Step 2：确认或询问文件路径

**情况 A：用户在初始命令中已提供路径（如 `/cv debate docs/requirement.md`）**

使用 `Read` 尝试读取该路径：
- 若失败：展示与【轻量盲审模式】Step 2 相同的路径错误提示，然后**询问用户**：「请重新输入文件路径：」
- 若成功：展示前 10 行摘要，继续 Step 3

**情况 B：用户未提供路径（如 `/cv debate`）**

询问用户：
```
📋 进入多轮闭环博弈模式。

请提供初始需求或设计文档的路径。
支持相对路径（如 docs/requirement.md）或绝对路径。

📄 文件路径：
```

收到用户回复后，用 `Read` 验证。若失败则重复提示路径错误信息并再次询问，直到成功或用户取消。

### Step 3：询问迭代轮数

询问用户：
```
🔁 请输入迭代轮数（默认 2 轮）：
```

解析用户回复：
- 若为空、或非正整数 → 使用默认值 `2`
- 若输入数字 `N`：
  - 如果 `N > 5`：提示「⚠️ 轮数较多（N 轮），预计成本较高，确认继续吗？」若用户否定则回到本步骤重新询问
  - 如果 `N < 1`：提示「轮数必须 ≥ 1，已重置为默认值 2」
  - 否则：使用 `N`

### Step 4：询问输出目录

询问用户：
```
📁 请输入输出目录（默认 outputs/）：
```

解析用户回复：
- 若为空 → 使用默认值 `outputs`
- 否则：使用用户输入的目录名（不需要验证目录是否存在，`cv-review` 会自动创建）

### Step 5：询问定向关注点

询问用户：
```
🎯 是否需要追加定向关注点？（可选，直接回车跳过）
   例如：重点审查并发安全、关注缓存策略等
```

解析用户回复：
- 若为空 → 不添加 `--instruction` 参数
- 否则：作为定向指令使用

### Step 6：执行多轮闭环博弈

向用户确认参数汇总：
```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 Debate 参数确认
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  文件路径：   [文件路径]
  迭代轮数：   [N] 轮
  输出目录：   [输出目录]/
  定向指令：   [定向指令，若为空则显示"无"]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
🚀 正在启动多轮闭环博弈...
   预计需要 1-3 分钟（取决于文档长度与轮数），请稍候。
```

使用 `Bash` 调用底层 CLI：

```bash
cv-review --file "<文件路径>" --mode debate --rounds <轮数> --output "<输出目录>" [<若定向指令非空> --instruction "<定向指令>"]
```

⚠️ **注意**：这是一个**长时间运行**的命令。执行期间请向用户展示等待提示：「⏳ 正在第 X 轮博弈中...」之类的进度感（虽然底层 CLI 不会输出中间进度，但你可以在等待期间保持用户知情）。

### Step 7：结果展示与后续

命令完成后，解析 stdout。`cv-review` debate 模式的 stdout 格式为：
```
[+] 交叉验证完成，文档已输出至: [绝对路径]
```

1. **报告完成**：
   ```
   ✅ 多轮闭环博弈已完成！
   📄 最终文档输出至：[输出文件的绝对路径]
   ```

2. **展示摘要**：使用 `Read` 读取最终文档的前 50 行，展示给用户。

3. **询问后续**：
   ```
   💬 接下来你可以：
      1. 回复「贴到对话」——我把完整文档贴进来讨论
      2. 回复「继续修改」——我根据文档内容帮你优化
      3. 回复「结束」——完成本次 debate
   ```

4. **根据用户选择执行**：
   - 「贴到对话」→ `Read` 读取完整文档内容并贴到对话中
   - 「继续修改」→ 进入正常的文档讨论与修改流程
   - 「结束」或忽略 → 完成

## 路径兼容性处理规范（重要）

在执行过程中，你必须特别注意路径的跨平台兼容性：

1. **接收阶段**：无论用户输入 `<` 什么路径格式（`/`、`\`、`//`、`\\`、带盘符、不带盘符），都原样保留传递给 `Read` 和 `Bash`。

2. **验证阶段**：始终使用 `Read` 工具验证路径是否存在。`Read` 工具本身具备跨平台路径解析能力。

3. **失败处理**：只要 `Read` 返回"文件未找到"或类似错误，**绝不要猜测路径或自动修正**，必须向用户明确报告并请求重新输入。

4. **传递阶段**：在组装 `Bash` 命令时，路径必须用**双引号 `"` 包裹**，防止以下情况导致命令解析错误：
   - 路径中包含空格（如 `My Documents/design.md`）
   - Windows 反斜杠被 Shell 误解为转义符

5. **展示阶段**：向用户展示路径时，优先展示**绝对路径**（如果 `Read` 成功，你可以从结果中得知实际解析后的绝对路径），让用户明确知道操作的是哪个文件。
