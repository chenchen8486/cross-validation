# Multi-Agent Debate Design: 基于多智能体博弈的系统架构与算法设计交叉验证框架

## 1. 背景与核心痛点
在复杂软件系统架构设计、学术科研算法推演以及前沿方案制定前期，设计文档的严谨性与完备性直接决定了后续工程的成败。然而，传统的单会话 AI 辅助工具（如单个 Chat 窗口或单实例 CLI 软件）在推敲复杂逻辑时，存在思维定势、用户谄媚以及长文本注意力分散等缺陷。

本仓库通过引入**“同行评审（Peer Review）”**机制，利用代码在内存中构建一个**双盲同行评审**的多智能体博弈系统，彻底隔离上下文，从而逼近更优的设计。

---

## 2. 解决方案对比：双 CLI 窗口 VS 自动化 API 隔离

| 特性 | 方案 A：多 CLI 窗口手动交叉验证 | 方案 B：底层 API 自动化沙盒隔离（本仓库） |
| :--- | :--- | :--- |
| **实施方式** | 开启两个终端会话，人工执行复制粘贴，充当“信使”驱动辩论 | 编写 Python 脚本控制输入，每次请求只传递最新成果，不携带历史轨迹 |
| **优点** | 流程直观，可直接利用现有 CLI 生态环境（本地文件读写、环境探查） | **绝对物理隔离**（盲审状态）、**上下文无污染**、**一键自动化闭环** |
| **缺点** | 频繁复制粘贴在万字长文下极其繁琐，开发体验碎片化 | 脱离了官方 CLI 工具自带的本地命令执行生态，更聚焦于顶层逻辑推演 |

---

## 3. 工程落地架构设计

本项目采用**配置与逻辑完全分离**的架构。为了避免在 JSON 文件中维护换行符带来的转义灾难，本版本全面采用直观的**文本文档格式（键值对与多行文本块）**来配置角色。同时，系统支持**单模型自我校对**与**多模型联合审计**两种模式。

### 3.1 目录结构
```text
.
├── config/
│   ├── api_settings.json      # 纯参数配置：各家大模型的 API 基础地址与 Key 变量名
│   └── prompts.txt            # 角色配置：无换行符压力，所见即所得的文本格式
├── outputs/
│   └── DESIGN_DOCUMENT.md     # 最终输出的经过交叉验证的高质量设计文档
├── run_debate.py              # 核心控制脚本：支持多模型、多通道无污染博弈流调度
└── requirements.txt           # 项目依赖
